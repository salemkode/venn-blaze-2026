# Development

Venn was generated by `npx create-expo-app@latest venn --yes` (create-expo-app 5.0.0), then reset using its `npm run reset-project` command on 17 November 2026. The app uses Expo 58, React Native 0.88 and Expo Router.

Use Node 22.13 or newer. Install with `npm ci`. Run `npm run setup:native` to generate native projects; do not hand-maintain ios/ or android/. Build a development client with `npm run ios -- --device <owned-udid>` or `npm run android -- --device <owned-serial>`. Metro is `npm start` on 8097; web is `npm run web` on 8099. Expo Go cannot load the local crypto module or Keychain.

The local package in modules/libauth-native replaces the older RN 0.81 adapter using Expo Modules and the same native crypto kernels. Its package name/version satisfies XO’s adapter peer; it is a local compatibility implementation, not the published adapter release. No peer checks are disabled. Wallet transaction construction remains in react-native-xo. Existing Keychain services are retained.

Run `npm test`, `npm run typecheck`, `npm run lint`, `npm run test:native-core` and `npx expo-doctor`. Node tests use WASM; they do not prove native crypto. Native proof must run the development check screen on an owned device with public test vectors only. Never screenshot or inspect a recovery phrase.

Run the development checks from the Expo developer menu → Development checks (or open `venn://development`). Use only its public vectors.

At this checkpoint, the remaining npm audit entries trace to the upstream [Picomatch advisory](https://github.com/advisories/GHSA-fc5q-39xc-vjpf). The locked versions have no patched npm release available at the time of this alpha.
